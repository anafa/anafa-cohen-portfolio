## Tooling

- No Node.js/npm — plain HTML/CSS/JS, no build step.
- **Local dev server serves `frontend/` as the site root** (`http://localhost:8000/`, not `/frontend/`) — required for Netlify deployment-readiness. Before starting the python server, `scripts/start.sh`/`start.ps1` copy `content/cv.json` → `frontend/content/cv.json` (gitignored — `content/cv.json` at the project root is the single source of truth; this copy is a disposable build/dev artifact regenerated every `scripts/start`). `main.js` fetches `content/cv.json` (relative, no `../`). **If new content files are added under `content/`, they won't be visible to the site until the copy step also copies them** — currently only `cv.json` is copied; extend the `cp`/`Copy-Item` line in both start scripts and in `netlify.toml`'s build command if that changes.
- **Netlify deployment**: `netlify.toml` at the repo root sets `publish = "frontend"` and a `build.command` that does the same `content/cv.json` copy. Site is live at `anafacohen.com`, auto-deploying on every push to `master` (GitHub repo `anafa/anafa-cohen-portfolio`, public). DNS: Cloudflare, CNAME records at `@` and `www` pointing to the Netlify site's `*.netlify.app` hostname, DNS-only (not proxied) so Netlify's own free SSL cert provisioning isn't interfered with.
- **Cache-busting**: `css/styles.css` and `js/main.js` load via `<link>`/`<script>` tags in `index.html` with a manual query string, bumped independently per file when it actually changes — **currently `styles.css?v=8`, `main.js?v=9`**. `content/cv.json` fetches with `{ cache: "no-store" }`. Bump the relevant version whenever a CSS/JS change doesn't seem to show up before assuming there's a logic bug.
- **Known Git Bash gotcha (fixed, root cause)**: MSYS assigns its own *virtual* PID numbers to processes, separate from the real Windows PID (`ps`'s `WINPID` column), only valid within the bash session that allocated them — a PID from one `start.sh` invocation can be meaningless (or wrong) by the time a later `stop.sh` invocation (a fresh bash session) tries to `kill` it, leaking the server silently. Fixed by having `start.sh` resolve and persist the real Windows PID (`ps -p $! | tail -1 | awk '{print $4}'`) and `stop.sh` use `taskkill //F //PID` instead of bash's `kill`. `start.ps1`/`stop.ps1` were never affected — PowerShell's `Start-Process`/`Stop-Process` use real Windows PIDs natively.
- **Placeholder-visibility saga (resolved — was never a code bug)**: earlier in the project, a user report of a leftover "Photo coming soon" placeholder surviving multiple genuinely-correct fixes (a `[hidden]`+`!important` CSS override, then full `.remove()`-based element removal — both verified correct via byte-level diffs of served content) turned out to be a **local browser-caching issue on the user's machine**, confirmed by comparing their browser's View Source output against a `curl` fetch of the identical URL at the same moment. Root cause never identified, but it doesn't reproduce in an incognito/private window, which is the user's working setup now. Lesson kept as a standing convention below (the `[hidden]` override) and as a debugging heuristic: if a "should have worked" fix keeps getting reported as broken across multiple genuinely-correct attempts, suspect the user's browser/environment (test incognito) before continuing to assume the code is wrong.

## Conventions (established, keep enforcing)

- **`[hidden] { display: none !important; }`** is declared once near the top of `css/styles.css` (Reset section) and must stay — covers any element using the `hidden` attribute/property against a class that sets its own `display` value (author rules otherwise always beat the UA default `[hidden]` rule regardless of specificity).
- **Prefer constructing only the DOM you need over hide/show toggling.** `buildLogo()`, `buildProjectImage()`, and the hero photo/placeholder all follow this: build the real `<img>` OR the placeholder `<div>`, never both-then-hide-one. The Projects accordion is the one deliberate exception (`.is-open` class toggle rather than remove/rebuild on every click, since it's a frequent, reversible, purely-client-side UI interaction — not the same situation as a one-time "is there real content or not" placeholder decision).
- Real content only — no lorem ipsum, no invented CV details, ever — see the Content section above for how this was specifically upheld while authoring the new project write-ups.
- Every `<img>` has descriptive alt text; placeholders have no `<img>` at all when unset (avoids empty/misleading alt).
- Respect `prefers-reduced-motion` for any animation — default (no-preference) styles live inside `@media (prefers-reduced-motion: no-preference)`, so reduced-motion users get the end state with no transition, not just a faster one.
- Mobile-first responsive layout: base CSS is the mobile layout, `@media (min-width: 768px)` layers on the desktop layout. The Projects grid instead uses fluid `repeat(auto-fit, minmax(...))` with no hard breakpoint at all (matches the redesign mockup's own approach) — don't add a breakpoint-based override for it without a real reason, the fluid reflow is intentional.
- Hero CTA links to `#contact` — a plain static `href` in the HTML, not JS-set.

Update this file whenever the structure above changes or new conventions are established.
